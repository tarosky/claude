# スキルセット棚卸しインタビュー

## ペルソナ

あなたは会社の定期1on1を行うマネージャーとして振る舞ってください。
ただし上から目線ではなく、**対等な立場で好奇心を持って聞く**こと。
目的はユーザーのスキルセット情報を最新に保ち、今後のClaude Codeの提案精度を上げることです。

## 使用場面

- 定期的なスキル棚卸し（四半期推奨）
- 大きなプロジェクトを終えた後
- 新しい技術を学んだ後
- キャリアの方向性が変わったと感じた時

## 手順

### 1) 現状の読み込み

`~/.claude/CLAUDE.md` の「スキルセット」セクションを読み、現在の記録内容を把握する。

```bash
cat ~/.claude/CLAUDE.md
```

### 2) 前回レビューの確認

メモリディレクトリにレビュー履歴があれば確認する。前回からの経過時間と、前回のフィードバック内容を踏まえてインタビューを調整する。

```bash
cat ~/.claude/projects/*/memory/skill_review_log.md 2>/dev/null || echo "初回レビュー"
```

### 3) インタビュー実施

以下のセクションを **1つずつ** AskUserQuestion で対話的に進める。一度に全部聞かない。

#### Phase A: スキルの変化

現在のスキルセットを提示した上で、以下を聞く：

1. **レベルアップしたもの** — 「前回から自信がついた技術はありますか？」
2. **新しく身につけたもの** — 「新しく使い始めた技術・ツールはありますか？」
3. **錆びついたもの** — 「最近触っていなくて、記載を下げたほうがいいものはありますか？」
4. **記載の修正** — 「現在の記載で事実と違う点、ニュアンスを変えたい点はありますか？」

各質問では、現在の記載内容を具体的に引用しながら聞くこと。「フロントエンドのところで React について "キャッチアップは遅め" と書いてありますが、今もそう感じますか？」のように。

**選択肢は入口、本音は自由記述で拾う**: AskUserQuestion の選択肢はあくまで会話の起点。ユーザーが選んだ項目や「その他」で気になる回答があれば、必ず自由記述のフォローアップで深掘りすること。「AWS/GCPインフラを選ばれましたが、具体的にどこまで踏み込みましたか？」のように、選択→深掘りをワンセットにする。記載を書き換える前に、選択肢の裏にある事情（なぜそう変わったのか）を言葉で確認する。

#### Phase B: 興味・関心の推移

5. **今もっとも興味があること** — 技術に限らず、仕事や創作活動含めて聞く
6. **興味が薄れたもの** — 以前は気になっていたが今はそうでもないもの
7. **半年後にやっていそうなこと** — 方向性の確認

この結果は CLAUDE.md のスキルセットセクションに「現在の関心」として追記する。

#### Phase B-2: キャリアの方向性

スキル単体ではなく、役割・キャリアの視点から聞く：

8. **現在の役割が今後求めるスキル** — 「今の役割（CTO等）が、これから求めてくるスキルは何だと思いますか？」
9. **3年スパンの到達点と差分** — 「3年スパンで到達したい状態と、そのために今埋めるべき差分は？」
10. **時間配分の希望** — 「"技術者として"と"経営者・マネージャーとして"、時間配分はどうありたいですか？」

このフェーズの回答は、次の「3.5) 成長ギャップの指摘」の材料になる。

#### Phase C: 環境の変化

11. **ツール・環境の変化** — 新しいエディタ、CLI、サービスなど
12. **仕事の変化** — 役割、プロジェクト、組織の変化

### 3.5) 成長ギャップの指摘（正直なアドバイザーとして）

インタビュー結果（特に Phase B / B-2）を踏まえ、**志向（半年後・3年後の目標）と現状スキル・現状の行動のギャップ**を率直に指摘する。CLAUDE.md の「私に対する態度」に従い、真実を和らげない。

- 志向に対して現状が追いついていない差分（例: ある技術の本番運用を目標に掲げているのに、触っているのは検証環境だけ、等）
- 志向に反して時間を割けていない領域と、その機会費用
- 避けている不快な課題があれば名指しする
- **スキル問題と組織問題を切り分ける**: 本人の学習で埋まるギャップなのか、それとも人事・体制・単一障害点など組織側の問題を個人の努力にすり替えていないかを見極めて指摘する

指摘はユーザーへのメッセージとして提示し、反応を受けてから CLAUDE.md 更新に進む。ユーザーの補正が入れば、それも記載に反映する。

### 4) CLAUDE.md の更新

インタビュー結果を踏まえて `~/.claude/CLAUDE.md` の「スキルセット」セクションを更新する。

更新ルール：
- 事実の変更のみ反映する。感想や曖昧な印象は書かない
- 既存の構造（本業・専門、フロントエンド、バックエンド等）を維持する
- 新しいカテゴリが必要な場合のみ追加する
- 「現在の関心」セクションを追加・更新する
- 変更箇所をユーザーに差分として提示し、確認を得てから書き込む

### 5) レビュー履歴の記録

現在のプロジェクトメモリに、レビュー実施日と主な変更点を記録する。

### 6) インタビュー自体へのフィードバック

最後に、**このインタビュープロセス自体**について聞く：

- 「今回のインタビューで聞かれなかったけど聞いてほしかったことはありますか？」
- 「質問の粒度や順番は適切でしたか？」
- 「次回に向けて改善してほしい点はありますか？」

フィードバック内容は `~/.claude/skills/skill-review/skill.md`（このファイル自体）の改善に使う。
具体的な改善提案があれば、ユーザーの許可を得てこのスキルファイルを更新する。

## 重要な注意事項

- **一度にすべてを聞かない**: 各フェーズで1〜2問ずつ、対話的に進める
- **押し付けない**: 「変化なし」は完全に正当な回答。無理に変更を探さない
- **具体的に聞く**: 「何か変わりましたか？」ではなく、現在の記載を引用して「これは今も正確ですか？」と聞く
- **選択肢で終わらせない**: AskUserQuestion の選択後は自由記述で必ず深掘りする。書き換えの根拠は「なぜそう変わったか」の言葉で確認する
- **ギャップ指摘を省略しない**: 成長ギャップの指摘（3.5）は、たとえ変化が少ない回でも行う。スキル問題か組織問題かを切り分けること
- **CLAUDE.md の更新は確認後**: 差分を見せて同意を得てから書き込む

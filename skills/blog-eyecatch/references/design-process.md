# デザインプロセス（タイトルからモチーフを作る・バッチでの重複回避）

## 手順1: タイトルだけで早合点しない

`wp-org-assets`の「プラグイン名だけで機能を早合点しない」と同じ注意点。タイトルは煽り気味・比喩的なことがあるため、記事のリード文や`category`が入力にあれば必ず読む。読んだ上で、モチーフのブリーフを1〜2文の日本語で書き出してから画像生成に進む。

例:
- タイトル「第三者によるWordPressの品質担保｜受け入れテストの種類と指摘への向き合い方」
- ブリーフ「第三者QA・受け入れテストの様子。虫眼鏡やチェックリストのような検証・検品のモチーフ。攻撃的・警告的にしすぎない（品質保証はネガティブな話ではないため）」

## 手順2: モチーフの配色

`#242424`（アウトライン）・`#A60C30`（アクセント）・白・`#E7D5D2`（面の塗り分け）のみで構成する（2026-09-15確定。`references/brand-guideline.md`）。派手な多色イラストにしない。`wp-org-assets`のicon.svgが「ブランド2色+白」で統一感を出しているのと同じ考え方。

実装上は、モチーフをSVGで描くのが既定（`--motif-svg`）。線画スタイルなので画像生成AIより線幅・配色が揃い、部分修正もできる。黒アウトラインは`stroke-width:6`、要素は3つ程度までに抑える。

## 手順3: モチーフ生成プロンプトの型

`scripts/generate_motif.py`に渡すプロンプトは、必ず次の禁止事項を含める:

- 文字・数字・ロゴ・透かしを一切含めない（英語でも日本語でも）
- 単純なモチーフ1点に限定する（複雑な人物シーンにしない）
- 背景は単色または単純なグラデーションにする（後でその上にタイトル文字を重ねるため、コントラストを崩す複雑な模様を避ける）
- ブランド配色（`references/brand-guideline.md`）の範囲に収める

## 手順3.5: アイソメトリックで描く（既定の画風）

デザイナー指定の画風は「フラット＋アイソメトリック寄り、`#242424`の太い輪郭線、差し色 `#A60C30`・`#C2042D`、
補助 `#DDDDDD`・白・`#F7ECE9`、グラデ・影なしで平面的に」。**アイソメトリックはセンスではなく座標変換**なので、
`scripts/iso.py` を使えば正確に描ける（画像生成AIに頼むより線幅・配色が揃い、あとから寸法を変えられる）。

```python
import sys; sys.path.insert(0, str(Path.home() / ".claude/skills/blog-eyecatch/scripts"))
from iso import Scene, WHITE, PALE, GRAY, RED
s = Scene(scale=17)
s.box((-6.5, -6.5, 0), (13, 13, 1.5), top=WHITE, left=PALE, right=GRAY)  # 段積みの台
open("motif.svg", "w").write(s.to_svg(width=520))
```

### 視点の角度（ハウススタイル: 方位角32° / 仰角45°）

`Scene(azimuth=..., elevation=...)` で視点を変えられる。既定値は正等角投影(45° / 35.264°)だが、
**アイキャッチでは 32° / 45° を使う**（2026-09-15にデザイナーと比較して決定）。

- 方位角を45°からずらすと左右非対称になり、「左斜め上から見下ろす」構図になる（45°のままだと正面から見た左右対称）
- 仰角を上げるほど上面が広く映る。og:imageの小さいサイズでも中身が読めるので、45°程度まで上げる価値がある
- **ただし上げすぎない。** 人物は正面向きで描くため、台を強く見下ろすほど人物との矛盾が目立ち「貼り付けた感」が出る。
  仰角55°で実際にそうなった

角度を変えて試すときは、モチーフの生成スクリプトに引数で渡せるようにしておくと比較が早い
（`python3 motif-iso.py <方位角> <仰角> [出力先]`）。

実際に踏んだ落とし穴を2つ、必ず頭に入れてから描くこと:

1. **地面に置いた円は必ず横長の楕円になる**（`rx = √1.5·r`, `ry = r/√2`、比 √3）。手描きで楕円比を
   目分量にすると一気に嘘くさくなる。`iso.py`の`poly2()`でXY平面の輪郭を投影すれば自動的に正しくなる。
2. **平たい箱の上に立てた細い要素は、箱の上面に隠れることがある。** 高さ1単位が画面Yに `cosφ` 効くのに対し、
   箱の上面は (幅+奥行)/2 単位ぶん `sinφ` 効いて画面Yに広がる。既定角では前者:後者 = 1:0.5 なので、
   **箱の(幅+奥行)/2 より低い突起は上面の奥角より下に来て消える。** 南京錠のつるを箱の高さ+1.45単位で
   立てたら完全に消えた（仰角を上げるほどこの条件は厳しくなる）。

人物は立体化せず正面向きで描くのがフラット・アイソメトリックの定石（`motif-iso.py`の`person()`参照）。

## 手順4: バッチ内でのモチーフ重複を避ける

記事本数分をまとめて生成する場合、同じような構図・モチーフばかりにならないよう、処理した記事とモチーフの対応を簡単なログ（例: `output/_motif-log.csv`に`slug,motif概要`を1行追記）に残しながら進める。次の記事のブリーフを作る際にこのログを見て、直近数件と被っていないか確認する。`wp-org-assets`が兄弟プラグインのアイコンを並べて重複を確認するのと同じ目的。

## 手順5: ユーザーに確認すべきタイミング

- ブランドカラー・フォントが未確定のまま初回本番生成に入る前
- 生成したモチーフに文字らしきものが写り込んでいた場合（差し替えて良いか、プロンプトを変えるかの判断）
- バッチ全体を見て「同じモチーフに偏っている」と感じた場合
